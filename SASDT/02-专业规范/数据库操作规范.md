# 数据库操作规范

> **版本**：V1.0 | **最后更新**：2026-07-25

---

## 核心原则

1. **先备份，再操作** — 任何 DDL/DML 操作前必须先确认备份可用
2. **先问人，再动手** — DROP/ALTER/TRUNCATE/RENAME 必须先经审批
3. **可逆优先** — 加列优先于改列，软删除优先于物理删除

## 强制规则

| 规则 | 说明 |
|------|------|
| ❌ 不执行未批准的 DDL | DROP/ALTER/DELETE/TRUNCATE/RENAME → 必须先问 |
| ❌ 不批量删除无 WHERE 条件 | DELETE 必须带 WHERE，确认影响行数 |
| ✅ 使用反引号包裹库名/表名 | `` `op_xxx` `` 而非 `op_xxx`，防止关键字冲突 |
| ✅ 软删除优先 | 业务表增加 `deleted_at` 字段，不物理删除 |
| ✅ 加列优先 | 新功能优先加列（ADD COLUMN），不改列（CHANGE/MODIFY） |
| ✅ 幂等建表 | `CREATE TABLE IF NOT EXISTS` + `DROP TABLE IF EXISTS` 搭配 |

## 数据库命名约定

- 公共库：`{project_name}_common`
- 运营商独立库：`{project_name}_{op_id}`
- 表名：小写 + 下划线，复数形式（`users`, `orders`）
- 字段名：小写 + 下划线（`created_at`, `operator_id`）
- **已存在的命名为常量**，不修改、不格式化、不替换

## 高危操作检查清单

执行任何高危操作前，逐项确认：

- [ ] 已获得人类（Allen）或总监的明确批准
- [ ] 数据库备份已确认可用（检查时间戳和文件大小）
- [ ] 测试环境已验证操作可执行
- [ ] 知道回滚方案（如何撤销本次操作）
- [ ] 操作窗口期已确认（非业务高峰期）
