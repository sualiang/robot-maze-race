# 密钥与安全规范

> **版本**：V1.0 | **最后更新**：2026-07-25

---

## 核心原则

**密钥存在于三个地方就是泄露**：源代码 + 配置文件 + commit 历史。任何地方都不应出现明文密钥。

## 强制规则

| 规则 | 说明 |
|------|------|
| ❌ 不把密钥写入代码 | 任何编程语言文件（.ts/.js/.py/.java 等）不得出现明文密钥 |
| ❌ 不把密钥写入配置 | .env 文件、config.json、docker-compose.yml 等不得出现明文密钥 |
| ❌ 不把密钥写入文档 | README、CLAUDE.md、技术方案文档、注释中不得出现密钥 |
| ❌ 不把密钥写入 commit message | git commit message 中不得出现密钥 |
| ✅ 使用环境变量 | 密钥通过环境变量注入，不从代码读取 |
| ✅ .gitignore 保护 | .env 等敏感文件必须在 .gitignore 中 |

## 密钥管理方案

| 密钥类型 | 存放位置 | 获取方式 |
|---------|---------|---------|
| 数据库密码 | 服务器 `.env`，权限 600 | SSH 到服务器读取 |
| API Key / Secret | 服务器 `.env`，权限 600 | SSH 到服务器读取 |
| GitHub Token | GitHub 个人设置 | 不写入代码或配置文件 |
| SSH 私钥 | `~/.ssh/`，权限 600 | 不传递，不备份 |

## 环境隔离

| 环境 | 用途 | 隔离方式 |
|------|------|---------|
| 本地开发 | 开发调试 | 本地 .env |
| 测试环境 | 集成测试 | Docker 命名空间隔离 |
| 正式环境 | 生产运行 | Docker 命名空间隔离 + 独立配置 |

**严格禁止**：将测试环境的数据/配置/密钥用于正式环境，反之亦然。
