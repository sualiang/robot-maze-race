# 角色全景图

> SASDT 体系由 6 个角色组成，分布在 4 个不同的 AI 平台上。
>
> **版本**：V1.0 | **最后更新**：2026-07-25

---

## 角色总览

| 编号 | 角色 | 平台 | 汇报对象 | 核心产出 |
|------|------|------|---------|---------|
| R01 | 项目/产品总监 | Claude Cowork | 人类 (Allen) | 需求文档、测试方案、验收结论 |
| R02 | 技术总监 | Claude Code CLI（子 Agent） | 项目/产品总监 | 架构方案、技术审查报告 |
| R03 | 开发工程师 | Claude Code CLI（子 Agent） | 项目/产品总监 | 代码实现、git commit、自测结果 |
| R04 | **测试工程师** | **豆包桌面客户端（本地 Agent 模式）** | 项目/产品总监 | 测试报告、Bug 清单 |
| R05 | 运维 | OpenClaw 云端 | 项目/产品总监 | 部署回执、巡检报告 |
| R06 | 项目审计 | 千问 (Qwen) | 人类 + 总监 | 审计报告、规则建议 |

## 平台分布

```
Claude Cowork ──────── 项目/产品总监（我）
         │
         ├── spawn ── Claude Code CLI ──── 技术总监
         │                        └─────── 开发工程师
         │
         ├── 飞书Bot ── 豆包桌面客户端 ──── 测试工程师（同机 Windows）
         │              OpenClaw ──────── 运维（云端服务器）
         │
         └── API ──── 千问 (Qwen) ────── 项目审计
```

## 角色间关系

| 关系 | 说明 |
|------|------|
| 总监 ↔ 技术总监/开发 | 我 spawn 子 Agent，任务驱动 |
| 总监 ↔ 测试/运维 | 飞书 Bot 指令，异步执行 |
| 总监 ↔ 审计 | 定时审计 + 事件触发 |
| 技术总监 vs 开发 | 平级，技术总监出方案，开发工程师编码 |
| 审计 vs 全员 | 监督关系，审计不参与决策 |

## 核心通讯矩阵

| 角色 | 通讯方式 | 指令特征 | 反馈特征 |
|------|---------|---------|---------|
| 技术总监 | spawn 子 Agent | 架构任务描述 + 格式要求 | 方案文档 |
| 开发工程师 | spawn 子 Agent | 开发任务 + 方案 + 验收标准 | commit hash + 自测 |
| 测试工程师 | 飞书 Bot | 测试范围 + 用例 + 验收标准 | 测试报告 + Bug + 截图 |
| 运维 | 飞书 Bot | 操作目标 + 安全约束 | 执行回执 |
| 项目审计 | 飞书群 + API | 定时/事件触发 | 审计报告 + 告警 |
